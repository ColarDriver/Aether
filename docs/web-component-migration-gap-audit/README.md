# Web Component Migration Gap Audit

Status date: 2026-05-27
Branch observed: `web-console-migration`

## Bottom Line

Aether web has a real Aether-owned React/TypeScript chat-rendering foundation. It can normalize persisted transcript messages and live WebSocket frames into typed blocks, render the main chat timeline, show user/assistant/thinking/tool/diff/prompt/status blocks, and run through basic web-console workflows.

It is not complete cc-haha/Hermes-style developer-console parity. The remaining gap is mostly workflow depth: richer per-tool lifecycle rendering, deeper task/subagent drill-down, post-edit conflict/acceptance workflows, repository/worktree launch controls, durable prompt recovery across backend restart, and broader browser/manual visual acceptance.

A practical completion estimate is:

- Foundation chat/runtime path: mostly complete.
- Coding-oriented tool UI: partial.
- Composer/workspace workflow parity: partial to mostly complete, improved with real directory drill-down for @workspace references, file preview/editing, and selected workspace context injection.
- Advanced developer-console controls: partial, with backend-connected session delete/rename/import/export/fork/rewind, MCP config/resource browsing, context compression, and workspace checkpoint primitives now present.
- Visual/browser acceptance: baseline smoke exists, including narrow-width workspace-reference interaction; deeper screenshots, responsive wrapping, and real-provider workflow coverage still needed.

## Important Missing Components Or Behaviors

1. Message lifecycle actions: quote, user edit-to-composer, user retry, assistant retry, fork, and rewind are now available when the target message is persisted. Remaining gaps are checkpoint-backed undo/replay, better conflict handling, and richer result-state feedback after these actions.
2. Full composer command surface: `/clear` now clears the visible web transcript and plan state, and @workspace references now support click, Enter/Tab, ArrowRight/ArrowLeft directory navigation, clickable path breadcrumbs, folder/file counts, per-reference path copy, removal, file preview, visible-token synchronization before sending, and provider-only attached context injection for selected workspace/text files. Remaining gaps are richer local panels, responsive stress coverage, and repository/worktree launch controls.
3. Rich edit/workflow cards: current changed-file card now has file classification, hunk counts, copyable paths, same-turn diagnostics by file, same-turn shell/LSP verification bundle view, and checkpoint-backed per-file restore for web runs. Remaining gaps are richer accept/reject semantics, diagnostics/verification follow-up actions, and conflict handling.
4. Deep task/subagent UI: inline summaries, task detail drawer, session task hierarchy, parent/child drill-down, recent assistant/tool observer messages from `messages.jsonl`, currently queued parent-to-child messages from `pending.jsonl`, delivered parent-to-child message history from `delivered.jsonl`, descendant child message stream filtering/collapse, duration/provider metadata, task follow-up messages, detail-level stop, session-bar quick stop, and task `result.json` artifact rendering with path copy, JSON copy, explicit URL opening, and local artifact path copy are now connected to current task APIs. Richer child transcript controls, deeper artifact routing, and richer result actions remain open.
5. MCP management: backend status/config/server/resource routes and the web `/mcp` inspector are now present. Remaining gaps are richer credential handling, more robust remote transport validation, accessibility/manual acceptance, and deeper resource/action rendering.
6. Tool-specific preview breadth: shell/read/search/web/todo/task/images plus file edit, notebook edit outputs, execution-state metadata, notebook lifecycle timelines from flat fields, nested timing records, and event arrays, LSP, browser-result screenshots, diagnostics, artifact bundle, provider web_search metadata, Codex/Anthropic hosted search metadata, raw Brave/Tavily/Anthropic/citation payload variants, Aether markdown web_search output, and spill-notice previews are started; browser visual acceptance, additional provider-specific web-search edge cases beyond current Codex/Anthropic/Brave/Tavily/Bocha/Aether shapes, deeper notebook lifecycle edge cases, and richer artifact actions beyond current copy/open/preview-copy routing still need dedicated renderers.
7. True context accounting: current token ring and context panel use active-run/session metadata and now normalize provider token fields including prompt/completion/cache/reasoning variants. They still do not reconstruct full prompt budget, model window pressure, or compaction state with high fidelity.
8. Prompt reconnect resilience: pending permission/approval prompts now survive browser WebSocket reconnect within the same backend process and are replayed to the new socket. If an old browser page reconnects with a stale startup token, the run socket refreshes the token from the served bootstrap document before retrying. The frontend now queues multiple pending permission/approval prompts by `prompt_id`, advances one prompt at a time, deduplicates replayed prompts, and consumes `prompt.resolved` without clearing unrelated prompts. Remaining gap is durable prompt recovery across backend restart, accessibility review, and broader manual stress coverage for multiple tabs.
9. Browser visual acceptance: baseline Playwright smoke now covers real App rendering for representative persisted/live/non-streamed chat, rich assistant Markdown rendering, notebook execution metadata/output rendering, provider web-search metadata/result rendering including nested provider snippets, task detail states, mobile-width overflow containment, narrow-width workspace references, confirmed sidebar session deletion, resizable side panels, and screenshot baselines for desktop chat, long terminal output, narrow workspace context, and permission diff modal. We still need broader device coverage and real-provider/manual sessions.

## Short Answer

The migration is at a usable foundation stage with stronger browser coverage, not completion. The core chat-rendering architecture is in place and several important components have been rebuilt in Aether-native TypeScript. However, several higher-level developer-console capabilities are still partial, especially post-edit conflict/acceptance workflows, deeper task/subagent controls, repository/worktree launch controls, durable prompt recovery, provider/manual acceptance, and expanded browser visual coverage.
